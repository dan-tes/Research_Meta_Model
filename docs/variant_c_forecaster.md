# Вариант C: табличный прогнозист «сколько улучшения ещё осталось»

Справочное описание модели для дипломной работы: на чём обучалась, что подаётся
на вход, что она предсказывает, как устроен инференс и какие получились метрики.
Реализация — [`meta_forecaster.py`](../meta_forecaster.py); применение в решении об
остановке — `SmartEarlyStoppingMultiStep._forecast_meta_gain` в
[`pytorch_version.py`](../pytorch_version.py).

Все числа ниже воспроизводятся командами `python meta_forecaster.py train` и
`python meta_forecaster.py eval`.

---

## 1. Постановка

По началу кривой валидационных потерь `val_loss[0..k−1]` предсказать **скаляр,
непосредственно нужный для решения об остановке**: `relgain` — какое
относительное улучшение `val_loss` (к текущему лучшему значению) ещё доступно за
следующие `H = 10` эпох.

Ранняя остановка затем сравнивает прогноз с бюджетом `epoch_penalty · H` и
останавливает обучение, когда `relgain` падает ниже бюджета `patience` эпох
подряд.

Вспомогательно модель предсказывает `plateau` — через сколько эпох `best-so-far`
выйдет на ε-окрестность своего итогового минимума; в решении об остановке эта
голова не используется, она диагностическая.

Ключевое отличие от первой (неудачной) версии прогнозиста: **прямой прогноз
целевого скаляра**, а не одношаговой дельты `val_loss` с последующей
авторегрессионной раскаткой на несколько эпох (та систематически предсказывала
«изменение ≈ 0» на быстро падающих кривых).

## 2. Данные

### 2.1. Генерация кривых обучения

Скрипт [`gen_curves.py`](../gen_curves.py). Для каждой задачи обучается
полносвязная сеть (MLP, 1–3 скрытых слоя, ReLU, dropout) полным прогоном на
**140 эпох**; на каждой эпохе записываются `val_loss` и `val_metric`
(accuracy для классификации, R² для регрессии) на фиксированной тестовой выборке.
Одна кривая ≈ 1–2 с на GPU.

Гиперпараметры варьируются по сетке `configs_for`:

| параметр | значения |
|---|---|
| (ширина, глубина) | (16, 1), (64, 2), (128, 2), (256, 3) |
| learning rate (Adam) | 5·10⁻³, 3·10⁻³, 1·10⁻³, 5·10⁻⁴, 3·10⁻⁴ |
| weight decay | 0, 10⁻³ |
| dropout | 0, 0.3 |
| размер обучающей выборки | 300, 800, 2000, 6000 (обрезается по размеру задачи) |
| зашумление меток (классиф.) | 0, 0.15 |

Комбинации перемешиваются фиксированным генератором; если их меньше, чем нужно
кривых, добираются повторами с новым `seed`. По умолчанию **100 кривых на
задачу** (`N_PER_TASK`, переопределяется через переменную окружения).

### 2.2. Обучающая выборка

`data/curves_train.jsonl` — **800 кривых, 8 задач** (по 100 каждой):

| задача | тип | источник |
|---|---|---|
| `mnist`, `fashion` | классификация (10 кл.) | torchvision, flatten 784 |
| `sk_digits` | классификация (10 кл.) | `sklearn.load_digits` |
| `sk_bcancer` | классификация (2 кл.) | `sklearn.load_breast_cancer` |
| `diabetes` | регрессия | `sklearn.load_diabetes` |
| `synth_reg_a`, `synth_reg_b` | регрессия | `make_regression` (20/40 призн., шум 12/30) |
| `student_cgpa` | регрессия | локальный CSV (успеваемость студентов) |

400 кривых классификации + 400 регрессии.

### 2.3. Held-out выборка

`data/curves_eval.jsonl` — **300 кривых, 3 задачи** (по 100):

| задача | тип | примечание |
|---|---|---|
| `cifar10` | классификация | MLP по «сырым» пикселям (flatten 3072), не CNN |
| `california` | регрессия | `fetch_california_housing` |
| `wine` | регрессия | `WineQT.csv`, предсказание оценки качества |

**Дисциплина held-out.** Обучающие и оценочные задачи не пересекаются: прогнозист
обучается только на `curves_train.jsonl`, а все метрики обобщающей способности
считаются только на `curves_eval.jsonl` — задачах, датасетах и формах кривых,
которых модель не видела.

## 3. Представление входа

### 3.1. Нормировка

Кривая `val_loss` делится поэлементно на своё первое значение `val_loss[0]`:
`p = val_loss / val_loss[0]`. Кривая всегда стартует с 1.0, признаки становятся
безразмерными и одинаковыми для кросс-энтропии (классификация) и MSE (регрессия).

### 3.2. Нарезка на обучающие примеры (окна)

Из каждой кривой длины `T = 140` нарезаются перекрывающиеся окна: для каждого
`k` от `PREFIX_MIN = 5` до `T − 2` с шагом 1 берётся префикс `p[0..k−1]` (вход) и
из полной кривой вычисляется целевая пара `(relgain, plateau)` в точке `k`.

Итого **≈ 133 окна на кривую**:
* обучающая выборка: 800 кривых → **106 400 окон**;
* held-out: 300 кривых → **39 900 окон**.

### 3.3. Признаки (21 штука)

Все считаются по нормированному префиксу `p` длины `k`; `d = diff(p)`.

| признак | смысл |
|---|---|
| `k` | сколько эпох пройдено |
| `p_last` | текущее значение `val_loss` (норм.) |
| `p_min` | лучшее достигнутое значение |
| `drop_so_far` | `1 − p_min` — насколько кривая уже упала от старта |
| `gap_to_min` | `p_last − p_min` — насколько текущее значение выше лучшего |
| `gap_to_min_frac` | то же, но как доля от общего падения `1 − p_min` |
| `epochs_since_best` | эпох с последнего рекорда `val_loss` |
| `frac_since_best` | `epochs_since_best / k` |
| `slope_all` | наклон линейной регрессии по всему `p` |
| `curv_all` | старший коэффициент квадратичной аппроксимации `p` (кривизна) |
| `slope_5`, `slope_3` | наклон по последним 5 и 3 точкам |
| `impr_5`, `impr_3` | улучшение `p` за последние 5 и 3 эпохи |
| `impr_ratio` | `impr_3 / impr_5` — улучшение ускоряется или затухает |
| `last_delta` | изменение за последнюю эпоху |
| `mean_delta_5` | среднее изменение за последние 5 эпох |
| `std_delta_5` | разброс изменений за последние 5 эпох (шум кривой) |
| `sign_changes_8` | число смен знака `d` за последние 8 эпох (осцилляции) |
| `acc` | `p[-1] − 2·p[-2] + p[-3]` — дискретное «ускорение» |
| `slope_ratio` | `slope_5 / slope_all` — локальный наклон относительно глобального |

По перестановочной важности на held-out наибольший вклад дают `slope_all`,
`curv_all`, `epochs_since_best`, `std_delta_5`, `frac_since_best` — то есть
глобальная форма кривой (наклон + кривизна) и «как давно не было улучшений».

## 4. Целевые переменные

Пусть `v` — вся нормированная кривая, `k` — длина префикса, `m0 = min(v[:k])`
(лучший `val_loss` на префиксе).

### `relgain` — основная

```
fut       = v[k : k+10]                       # следующие H = 10 эпох
fut_best  = min(fut)
relgain   = max(0, (m0 − min(m0, fut_best)) / m0)
```

Относительное улучшение лучшего `val_loss` за горизонт 10 эпох. Всегда ≥ 0.

Распределение на обучающей выборке: **медиана 0**, среднее 0.034, 90-й
перцентиль 0.102, максимум 0.93; **ненулевые — 33 % окон**. То есть на 2/3 окон
кривая уже вышла на плато и `relgain = 0`; ценность модели — точно распознать
оставшуюся треть, где улучшение ещё идёт.

### `plateau` — вспомогательная

Число будущих эпох до момента, когда `best-so-far` подойдёт на `PLATEAU_EPS = 0.02`
(в долях `val_loss[0]`) к итоговому минимуму остатка кривой; обрезано сверху
`PLATEAU_CAP = 40`.

## 5. Модель

`sklearn.ensemble.HistGradientBoostingRegressor` — градиентный бустинг на
гистограммах, две независимые модели (по одной на каждый таргет), обученные на
одном и том же наборе из 21 признака.

| гиперпараметр | значение |
|---|---|
| `max_iter` (макс. деревьев) | 500 |
| `learning_rate` | 0.05 |
| `max_leaf_nodes` | 31 |
| `min_samples_leaf` | 40 |
| `l2_regularization` | 1.0 |
| `early_stopping` | да, `validation_fraction = 0.15` |
| `random_state` | 0 |

Внутренняя ранняя остановка бустинга отсекла обучение на **400 деревьях** для
`relgain` и на **454** для `plateau`. Функция потерь — квадратичная (по
умолчанию у `HistGradientBoostingRegressor`), метрика при отборе признаков и в
отчёте — MAE.

Обученная пара моделей + список признаков + конфиг сохраняются в
`models/meta_forecaster.pkl` (`joblib`). Опционально поддерживается
`XGBRegressor` (`MODEL_KIND = "xgb"`), в основной конфигурации не используется.

### Оценка при обучении — GroupKFold по задаче

Чтобы окна одной кривой (и одной задачи) не «протекали» между train и
validation, кросс-валидация делается по группам-задачам: 8 фолдов, в каждом одна
задача целиком в отложенной части. Это оценка «на новой задаче того же
пайплайна» — более мягкая, чем held-out из §2.3, но честная относительно
переобучения на конкретную кривую.

## 6. Как происходит прогноз (инференс)

В `SmartEarlyStoppingMultiStep` на каждой эпохе после `min_epochs = 10`:

1. Берётся вся история `val_loss` до текущей эпохи (`k ≥ 5`, иначе прогноз не
   считается и происходит откат на линейный тренд).
2. Нормировка: `p = val_loss / val_loss[0]`.
3. Считаются те же 21 признак, что при обучении (`features_from_prefix`).
4. `relgain_hat = clip( GBM_relgain.predict(features), 0, 1 )`.
5. **Решающее правило:**
   ```
   budget = epoch_penalty · meta_horizon          # meta_horizon = 10
   если relgain_hat < budget:  counter += 1
   иначе:                       counter = 0
   если counter ≥ patience (2): СТОП
   ```
   `epoch_penalty` для этой стратегии = **0.003** (`PENALTY_BY_STRAT` в
   `eval_early_stopping.py`); он вдвое меньше, чем у стратегии на линейном тренде,
   потому что бюджет умножается на горизонт 10, а не 5.
6. При любой ошибке (нет `.pkl`, слишком короткая история) — тихий откат на
   линейный тренд.

Прогноз строится **по одной точке** (текущему префиксу) на каждой эпохе;
авторегрессии нет.

## 7. Результаты

### 7.1. Точность прогноза `relgain`

| выборка | MAE | R² |
|---|---|---|
| GroupKFold по задачам (на `curves_train`) | 0.0152 | +0.718 |
| **held-out (`curves_eval`, 39 900 окон)** | **0.0074** | **+0.460** |
| held-out — базлайн: линейная экстраполяция | 0.0241 | −7.806 |

Базлайн (то, что делает стратегия `smart_trend`) — линейная экстраполяция
`val_loss` по окну из 6 эпох. На held-out градиентный бустинг **точнее в ~3.3×**
по MAE; отрицательный R² базлайна означает, что линейный прогноз на held-out
кривых хуже, чем константа «улучшений нет».

По задачам (MAE `relgain`, GBM / базлайн):

| задача | GBM | линейный тренд |
|---|---|---|
| `california` | 0.0149 | 0.0490 |
| `cifar10` | 0.0037 | 0.0084 |
| `wine` | 0.0037 | 0.0150 |

### 7.2. Точность бинарного решения «продолжать обучение?»

Доля окон, где `relgain_hat ≥ budget` совпадает с истиной `relgain ≥ budget`
(held-out):

| бюджет | GBM | линейный тренд | доля «продолжать» (истина) |
|---|---|---|---|
| 0.030 | 0.939 | 0.902 | 0.106 |
| 0.060 | 0.967 | 0.932 | 0.051 |
| 0.150 | 0.989 | 0.960 | 0.013 |

Классы сильно несбалансированы (обычно верно «стоп»), поэтому здесь важнее MAE
регрессии и бенчмарк ниже.

### 7.3. Точность `plateau`

Held-out: MAE 3.74 эпохи, R² +0.386 (cap 40).

### 7.4. В роли стратегии ранней остановки

Полный бенчмарк ([`eval_early_stopping.py`](../eval_early_stopping.py), fig7) —
обучение MLP на MNIST / CIFAR-10 / Wine при разных размерах выборки, стратегия
`smart_meta` при `epoch_penalty = 0.003`, усреднение по (задача, размер, seed):

| стратегия | эпох (доля от классической `early`) | потеря качества до oracle |
|---|---|---|
| `early` (patience = 5) | 1.00 | 1.7 % |
| **`smart_meta` (вариант C)** | **0.62** | **5.3 %** |
| `smart_trend` (линейный тренд) | 0.64 | 5.7 % |
| `param` (фит экспоненты) | 0.59 | 7.7 % |

После калибровки штрафа `smart_meta` и `smart_trend` эквивалентны; параметрический
фит отстаёт. Ни одна прогнозная стратегия не превосходит классическую `early` по
итоговой метрике — цель варианта C не в этом, а в экономии ~35 % эпох при
контролируемой (≈ единицы процентов на знакомых по форме кривых) потере качества.

Отдельный разбор по режимам ([`analyze_regime.py`](../analyze_regime.py), fig8):
на held-out кривых `early` оказывается ближе всех к oracle в 96 % случаев;
преимущество GBM над линейным трендом проявляется не в медианном качестве
(там паритет), а в устойчивости — он не разваливается, как фит экспоненты, на
кривых, которые к моменту решения ещё далеки от плато.

## 8. Ограничения

* Прогноз строится по `val_loss`, а решение в итоге принимается ради `val_metric`
  (accuracy / R²). На задачах, где `val_loss` выходит на плато раньше метрики
  (например, MLP по пикселям CIFAR-10), точный детектор плато `val_loss` всё
  равно останавливает слишком рано — до 12–17 % потери качества.
* Held-out — 3 задачи; `california` численно нестабильна при высоком learning
  rate, `wine` быстро сходится. Расширение набора задач усилило бы выводы.
* Модель обучена под конкретный пайплайн (MLP, Adam, 140 эпох); перенос на
  другие архитектуры/оптимизаторы не проверялся.
